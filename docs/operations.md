# 운영 가이드

## 환경 구성

운영과 사전 검증용 Supabase 프로젝트를 분리합니다. Vercel에는 Preview와 Production 환경별로 다음 값을 각각 등록합니다.

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` (서버 전용, 브라우저에 노출 금지)
- `ADMIN_EMAIL_ALLOWLIST` (쉼표로 구분한 승인 관리자 이메일)
- `APP_URL` (환경별 공개 주소, 끝 `/` 제외)

Supabase Auth의 URL Configuration에 `APP_URL`과 `APP_URL/auth/callback`을 허용하고, 공개 가입을 끕니다. 비밀번호 최소 길이는 12자, 영문 대·소문자와 숫자 포함으로 설정합니다. 비밀번호 재설정을 실제로 사용할 때는 운영 SMTP도 연결합니다.

## 배포 순서

1. Supabase 대시보드에서 즉시 복구 가능한 백업 또는 PITR 상태를 확인합니다.
2. staging 프로젝트를 연결한 뒤 `npx supabase db push --dry-run`으로 적용 목록을 검토합니다.
3. `npx supabase db push` 후 관리자 가입, 학교 생성, 업무 업로드, 회차 개시, 코드 발급, 제출·수정, 마감, Excel·인쇄를 전 과정 점검합니다.
4. 운영 DB에도 같은 마이그레이션을 적용합니다.
5. Vercel Preview 배포에서 점검한 동일 산출물을 Production으로 승격합니다.
6. `/api/health`가 HTTP 200과 `status: ok`를 반환하는지 확인합니다.

DB 마이그레이션을 적용한 뒤 구버전 앱을 다시 배포하지 않습니다. 문제가 생기면 먼저 앱 배포를 직전 버전으로 되돌리고, DB는 백업 복구 또는 별도로 검증한 순방향 보정 마이그레이션으로 처리합니다.

## 설문 운영

1. 업무 목록을 확정합니다. 회차를 연 뒤에는 그 회차의 문항이 스냅샷으로 고정됩니다.
2. 시작·마감 시각을 확인하고 회차를 엽니다.
3. 필요한 수만큼 참여코드를 발급해 내려받은 Excel을 접근 제한된 학교 저장소에 보관합니다. 원본 코드는 DB에 저장되지 않아 재다운로드할 수 없습니다.
4. 미사용 코드가 유출되면 끝자리로 찾아 폐기한 뒤 새 코드를 발급합니다.
5. 응답자는 마감 전까지 같은 코드로 제출 내용을 수정할 수 있습니다.
6. 마감 후 결과 Excel과 인쇄/PDF를 내려받아 보관하고 회차를 보관 처리합니다.

## 개인정보와 보존

이름·이메일·교직원 식별값은 응답에 저장하지 않습니다. 참여코드는 SHA-256 해시만 저장합니다. 업무분장 PDF/Excel은 요청 처리 중 메모리에서 규칙 기반으로 읽고 외부 AI 서비스로 보내지 않습니다.

보존 기간이 끝나면 결과 파일을 필요한 기록물 저장소에 보관한 후 관리자 화면에서 회차를 `보관`하고 `영구 삭제`합니다. 삭제하면 회차, 코드, 문항 스냅샷, 응답이 연쇄 삭제되며 되돌릴 수 없습니다.

## 장애 대응

- 입장 실패: 코드 오타·폐기 여부, 회차 상태, 시작·마감 시각을 확인합니다.
- 제출 실패: 모든 문항의 두 점수가 선택됐는지와 회차 마감 여부를 확인합니다.
- 결과 누락: 유효 코드의 제출 수와 Excel 응답 시트를 대조합니다.
- 배포 장애: Vercel 직전 정상 배포로 롤백하고 Functions 로그를 확인합니다.
- DB 장애: 쓰기 작업을 중단하고 Supabase 로그와 백업 시점을 확인한 뒤 복구합니다.
